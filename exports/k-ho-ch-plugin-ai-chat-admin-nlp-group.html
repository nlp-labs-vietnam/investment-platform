Lộ trình triển khai

1 Foundation – Database & AI Service Layer Tuần 1–2
  • › Tạo 4 migration: ai_chat_sessions, ai_chat_messages, ai_audit_logs, scheduled_publishes
  • › Thêm cột scheduled_at, published_by_ai vào bảng properties và blogs
  • › Tạo app/Services/AiService.php — abstraction layer hỗ trợ OpenAI / Gemini / Azure / Ollama
  • › Thêm config config/ai.php: provider, API key, model, system prompt mặc định
  • › Thêm các biến môi trường vào .env.example: AI_PROVIDER, OPENAI_API_KEY…
  • › Tạo Models: AiChatSession, AiChatMessage, AiAuditLog, ScheduledPublish
2 Chat UI & API – Popup Widget Tuần 2–3
  • › Tạo AiChatController với routes: POST /admin/ai/chat, GET /admin/ai/history, DELETE /admin/ai/session
  • › Tạo Blade component resources/views/admin/partials/ai-chat-widget.blade.php
  • › Inject vào layouts/app.blade.php trước </body>
  • › Viết JS widget: open/close, send message, stream response (SSE hoặc polling), markdown render
  • › Truyền context vào widget: data-page, data-model-type, data-model-id từ mỗi trang admin
  • › Tích hợp CSRF token, xử lý session admin đang đăng nhập
3 Content Actions – Editor, Audit, Scheduler Tuần 3–5
  • › Content Generate: AI sinh mô tả property/blog từ title → điền vào editor (TinyMCE/Quill) qua JS postMessage
  • › Rewrite: Endpoint POST /admin/ai/rewrite nhận đoạn văn, trả về phiên bản mới
  • › Auto-translate: Gọi AI dịch nội dung sang các language trong bảng languages, lưu vào blog_details / page_details
  • › Audit: Endpoint POST /admin/ai/audit — AI phân tích property/blog, trả về điểm và danh sách vấn đề
  • › Audit log: Mọi action AI ghi vào ai_audit_logs (admin_id, model_type, model_id, action, before, after, timestamp)
  • › Publish ngay: Chat "publish này" → AI xác nhận → AiChatController@publishNow set status=1
  • › Lên lịch: Chat "đăng lúc 8h sáng mai" → AI parse datetime → lưu scheduled_publishes → dispatch ScheduledPublishJob
  • › Upload ảnh qua chat: Drag-drop file vào chat widget, backend xử lý qua Upload trait hiện có, gắn vào model
4 Polish – Audit Dashboard, Phân quyền, Tests Tuần 6–8
  • › Trang /admin/ai/audit-log — DataTable xem lịch sử tất cả action AI
  • › Trang /admin/ai/scheduled — quản lý danh sách bài đã lên lịch, cancel, reschedule
  • › Tích hợp Role Permission: thêm permission ai_chat, ai_audit, ai_schedule vào hệ thống roles_permissions hiện có
  • › Rate limiting: giới hạn số request AI/phút/admin để kiểm soát chi phí
  • › System prompt theo ngữ cảnh: property prompt khác blog prompt khác audit prompt
  • › Tests: Feature test cho AiChatController, Unit test AiService mock
  • › Thêm vào sidebar admin: mục "AI Assistant" với submenu Chat, Audit Log, Scheduled

Rủi ro & Giải pháp

Rủi roMức độGiải pháp
Chi phí API AI cao khi sử dụng nhiều Cao Rate limit per admin, cache response, dùng model nhỏ (GPT-4o-mini) cho task đơn giản
AI trả về nội dung sai/không phù hợp Trung bình Mọi thay đổi đều có bước "Confirm" trước khi lưu, lưu diff before/after trong audit log
Scheduled job không chạy (queue down) Trung bình Dùng schedule:run kiểm tra lại, hiển thị trạng thái job trong UI, email thông báo nếu fail
Admin không có quyền vô tình publish nhầm Thấp Kiểm tra Role Permission trước mọi action, log rõ ràng admin nào thực hiện
API key bị lộ Cao Lưu trong .env, không expose ra frontend, mọi request AI đi qua backend
